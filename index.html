Dominio 1

Manage identity, access, and governance

Gestión de identidad, acceso y gobernanza

Protege la línea de entrada del entorno: quién accede, con qué privilegios y bajo qué políticas. Este dominio conecta Microsoft Entra ID con el control de acceso (RBAC, PIM), la protección de secretos (Key Vault) y la gobernanza mediante Azure Policy.

8 preguntas de práctica en el quiz

Microsoft Entra ID (antes Azure Active Directory) es el servicio de identidad y acceso de la nube de Microsoft: gestiona usuarios, grupos, aplicaciones y dispositivos, y permite federación con identidades externas (B2B/B2C) y con otros proveedores cloud.

  • Tipos de cuenta: usuarios miembros e invitados, grupos de seguridad y equipos, aplicaciones y service principals.
  • Identidades híbridas: Microsoft Entra Connect sincroniza con Active Directory on-premises; la identidad administrada (managed identity) resuelve credenciales en recursos Azure.
  • Protección: Entra ID Protection evalúa riesgo de inicio de sesión y de usuario, y Conditional Access toma decisiones con ese contexto.
  • Escenario de examen: distinguir cuándo usar Entra ID (identidad cloud), service principal (aplicación) o managed identity (recurso Azure sin secretos).

Azure RBAC asigna roles sobre ámbitos jerárquicos: grupo de administración → suscripción → resource group → recurso. Los permisos se heredan hacia abajo y se conceden con el principio de mínimo privilegio.

  • Componentes: seguridad (quién), rol (qué puede hacer) y ámbito (dónde aplica).
  • Microsoft Entra PIM: roles elegibles que se activan just-in-time con aprobación, justificación, MFA y límite de duración.
  • Revisión de acceso: auditoría periódica de asignaciones para eliminar privilegios innecesarios.
  • Cuidado: Owner no debe repartirse; Owner incluye la capacidad de asignar roles.

Key Vault centraliza claves, secretos y certificados con control de acceso granular, registro de auditoría (diagnostic logs) y políticas de retención.

  • Tipo de recurso: Managed HSM ofrece un HSM dedicado y aislado (FIPS 140-2 Nivel 3) para claves maestras de cliente.
  • Acceso: modelo RBAC (recomendado) o access policies heredadas por vault.
  • Protección: soft delete y purge protection evitan la eliminación accidental o maliciosa.
  • Integración: las aplicaciones usan identidades administradas para leer secretos sin guardar credenciales en el código.

Azure Policy evalúa recursos y planes de recursos para garantizar que la configuración cumpla estándares. Las iniciativas (initiatives) agrupan varias políticas bajo un objetivo.

  • Efectos comunes: Deny bloquea cambios inválidos, Audit solo registra desviaciones, Modify aplica cambios (p. ej. tags) y DeployIfNotExists crea el componente faltante.
  • Remediación: las tareas de remediation corrigen recursos existentes que incumplen la política.
  • Alcance: se asignan en management groups, suscripciones, resource groups o recursos, con exclusiones.
  • Complemento: Regulatory compliance en Defender for Cloud mapea las políticas contra estándares (ISO, SOC, PCI DSS).

Las políticas de acceso condicional combinan señales (usuario, ubicación, dispositivo, riesgo, aplicación) con controles (MFA, bloqueo, tokens de acceso) para decidir si se concede el acceso.

  • Señales: riesgo de usuario/sesión de Entra ID Protection, dispositivo conforme, ubicación, tipo de cliente.
  • MFA resistente al phishing: FIDO2 security keys, passkeys y Windows Hello for Business; evitan MFA fatigue e ingeniería social frente a SMS/OTP.
  • Sin contraseña: passwordless con FIDO2, WH4B y Authenticator con number matching.
  • Buenas prácticas: empezar con modo informe (Report-only), excluir una cuenta de emergencia y no bloquear al administrador global.

Dominio 2

Secure storage, databases, and networking

Protección de almacenamiento, bases de datos y redes

Reduce la superficie de exposición de los datos en reposo y en tránsito: firewalls de almacenamiento, auditoría en bases de datos, segmentación de red con NSG/ASG, conectividad privada y perímetro de defensa con Firewall y DDoS.

8 preguntas de práctica en el quiz

Las cuentas de almacenamiento deben restringirse a redes y identidades conocidas; la exposición pública innecesaria es una de las fallas más comunes en los casos de examen.

  • Firewall de la cuenta: reglas de IP y de red virtual; desactiva el acceso desde todas las redes y usa Private Endpoints.
  • Acceso: autenticación con Entra ID (OAuth/RBAC) o SAS cortas y con permisos mínimos; evitar claves de cuenta compartidas.
  • Defender for Storage: detecta datos sensibles, credenciales expuestas, malware y patrones de acceso anómalos en blobs.
  • Resiliencia de datos: soft delete (blobs, snapshots, versioning), retención inmutable y cifrado con claves de cliente (CMK).

El dominio exige conocer los mecanismos de detección y trazabilidad en Azure SQL Database y SQL Server en máquinas virtuales.

  • Auditing: registra eventos de base de datos y envía los logs a cuenta de almacenamiento, Log Analytics o Event Hub (para integrarlos con Sentinel). Amazon S3 no es un destino válido.
  • Microsoft Defender for Azure SQL: alerta sobre SQL injection, acceso anómalo y amenazas de la base de datos.
  • Cifrado: TDE en reposo, Always Encrypted para datos sensibles en cliente y encriptación de conexión con TLS.
  • Acceso: usuarios contenidos e identidades de Entra ID (SQL authentication/Entra-only) reducen el uso de sa.

Los grupos de seguridad de red (NSG) filtran tráfico en la capa 3/4 hacia y desde interfaces de red y subredes, con reglas de prioridad numeradas.

  • Prioridad: el número más bajo se evalúa primero (100 antes que 4096); si no hay coincidencia aplica DenyAllInBound por defecto.
  • Ámbitos: NSG en subred (protege todas las NIC) y/o en NIC individual (regla más específica gana).
  • ASG: agrupa NIC con el mismo perfil de puertos para escribir reglas por nombre de aplicación en vez de rangos de IP.
  • Buenas prácticas: restringir administración remota (3389/22) a fuentes conocidas y usar Azure Bastion.

Azure Private Link conecta servicios PaaS a una VNet mediante un Private Endpoint con IP privada, manteniendo el tráfico dentro de la red privada del cliente.

  • Private Endpoint: NIC privada que representa a Azure SQL, Storage, Key Vault, Cosmos DB, etc.
  • Private DNS: zona vinculada para que la resolución del nombre apunte a la IP privada.
  • Frente a service endpoints: Private Link resuelve el aislamiento completo del recurso, no solo de la red de origen.
  • Redundancia: combinar con VNet peering y zonas de disponibilidad según el RTO/RPO.

El control de tráfico entre redes y hacia Internet complementa la segmentación interna con reglas centralizadas y mitigación de ataques a escala.

  • Azure Firewall: reglas de red (IP/puertos), reglas de aplicación (FQDN HTTP/S), Threat Intelligence, inspección privada entre VNet y Azure Firewall Policy gestionada.
  • Tipos: Standard y Premium (con TLS inspección y detección de amenazas basada en inteligencia).
  • DDoS Protection: planes Network Protection e IP Protection con mitigación automática y protección de coste.
  • WAF: Application Gateway/Front Door protegen aplicaciones web contra el OWASP Top 10; un NSG no inspecciona capa 7.

Dominio 3

Secure compute

Protección del cómputo: IA, VMs, contenedores y aplicaciones

Protege dónde corre el código: desde cargas de IA (Copilot, agentes y modelos) hasta máquinas virtuales, clústeres AKS, Azure Functions, App Service y la defensa perimetral con WAF.

7 preguntas de práctica en el quiz

Las cargas de IA introducen riesgos nuevos: fugas de datos hacia modelos, agentes con privilegios y superficie de exposición en prompts y conectores.

  • Copilot for Security: investiga en lenguaje natural con un LLM orquestado por capacidades (plugins) y contexto de productos Microsoft.
  • DSPM: Data Security Posture Management descubre y clasifica datos sensibles y evalúa su riesgo en la nube.
  • Microsoft Entra Agent ID: identidad dedicada y gobernada para agentes de IA, con permisos y Conditional Access.
  • Defender for AI: plan de Defender for Cloud orientado a proteger aplicaciones y agentes de IA (modelos, datos y configuración).

La protección de VM combina cifrado del disco, arranque verificado, acceso temporal a administración y gestión unificada del inventario híbrido.

  • Cifrado: Azure Disk Encryption (BitLocker/dm-crypt gestionado por Key Vault) y cifrado en host con claves de cliente.
  • Trusted Launch: habilita Secure Boot (integridad de la cadena de arranque) y vTPM (mediciones y claves protegidas).
  • Just-in-Time (Defender for Servers): abre RDP/SSH solo durante una ventana aprobada y con reglas NSG temporales.
  • Azure Bastion: conexión RDP/SSH a través del portal por TLS sin IP pública expuesta; Azure Arc extiende políticas y Defender a recursos híbridos y multicloud.

En AKS la seguridad abarca el plano de control, los nodos, los manifiestos y las credenciales que usan los pods en ejecución.

  • Workload Identity (OIDC): los pods asumen una identidad administrada federada con Entra ID, sin secretos en YAML.
  • Defender for Containers: protege el clúster, las imágenes del registro y el trabajo en ejecución, con alertas y recomendaciones.
  • Gobernanza: Azure Policy para Kubernetes aplica restricciones (p. ej. prohibits privileged containers, require labels).
  • Buenas prácticas: RBAC de Kubernetes, isolation de nodos (system/user node pools) y secretos en Key Vault con CSI driver.

Las aplicaciones web y serverless se exponen vía HTTP, por lo que la protección combina identidad, restricciones de acceso y defensa en capa 7.

  • App Service: access restrictions por IP/VNet, identidad administrada para datos y despliegue sin credenciales.
  • Functions: claves de función rotadas, integración con Key Vault y acceso mediante identidad administrada.
  • Azure WAF: se despliega en Application Gateway o Front Door y aplica el Core Rule Set del OWASP Top 10 (inyección, XSS, etc.).
  • Defender for App Service: alerta de explotación, escaneo de amenazas y detección de bots/malware en el sitio.

Dominio 4

Manage and monitor security posture

Gestión y monitorización de la postura de seguridad

Mide, prioriza y responde: postura continua con Defender CSPM, protección de cargas con planes de Defender for Cloud, detección con Sentinel, análisis asistido con Security Copilot y correlación con Defender XDR y EASM.

7 preguntas de práctica en el quiz

Defender for Cloud reúne la gestión de la postura (CSPM) y la protección de cargas (CWPP) en un único portal con recomendaciones, Secure Score y cumplimiento normativo.

  • Plan gratuito: recomendaciones, Secure Score, evaluaciones de cumplimiento y CSPM básico.
  • Defender CSPM: plan avanzado con grafo de rutas de ataque (attack paths), evaluación de riesgos, gestión de identidades y capacidades DevSecOps.
  • Secure Score: mide la adopción de mejores prácticas y permite comparar el progreso entre tenants.
  • Conectores: AWS, GCP y entornos híbridos vía Azure Arc para una postura multicloud.

Cada plan especializado añade detecciones y recomendaciones específicas del tipo de recurso, activables por suscripción con nivel de precios Estándar.

  • Defender for Servers: agente de máquina virtual, análisis de vulnerabilidades, acceso JIT y AMA.
  • Defender for Containers: AKS/registros/imagenes y trabajo en ejecución.
  • Defender for Storage, App Service, Databases, DNS, Key Vault, Resource Graph y AI apps: protección específica de cada recurso.
  • Alertas: se envían a Sentinel, Logic Apps o herramientas externas para su remediación.

Sentinel centraliza registros de fuentes cloud y on-premises, correlaciona amenazas con reglas de análisis y automatiza la respuesta con playbooks (SOAR).

  • Consulta: Kusto Query Language (KQL) para reglas, hunting e investigaciones en Log Analytics.
  • Correlación: reglas de análisis, Fusion (ataques multi-etapa) y alertas con incidentes agrupados.
  • Automatización: playbooks con Logic Apps, respuesta a Defender y usuarios bloqueados vía Entra.
  • Coste: basado en ingesta de datos y retención; usar tablas de auditoría eficientes y conexores nativos.

La operativa moderna combina detección unificada con análisis asistido por IA para reducir el tiempo de investigación y contención.

  • Microsoft Security Copilot: LLM con orquestador de seguridad y capacidades de Defender, Entra, Sentinel e Intune para resumir, investigar y generar KQL.
  • Defender XDR: correlaciona correo, identidad, endpoint y colaboración en incidentes unificados con acciones automatizadas de respuesta.
  • Investigación: Explorer/Advanced Hunting permite seguir un ataque entre dominios (usuario → correo → endpoint).
  • Medición: MTTD/MTTR y reducción de ruido de alertas como métricas del programa de seguridad.

Conocer el perímetro externo es prerequisite para reducir el riesgo: activos no gestionados suelen ser la vía de entrada en los estudios de caso del examen.

  • Defender EASM: descubre y monitorea activos expuestos a Internet, incluido el shadow IT no inventariado.
  • Inventario: dominios, IPs, servicios públicos, certificados y vulnerabilidades asociadas.
  • Integración: sus hallazgos alimentan recomendaciones y riesgos dentro de Defender for Cloud.
  • Operación: combinación de alertas de Defender, Sentinel, EASM y Workbooks para el seguimiento del posture management.
